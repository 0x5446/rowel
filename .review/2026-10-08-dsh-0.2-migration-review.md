## 问题与处置（去重）
1. 401 不能作版本判据（0.1.2+ 都回 401）→ D1 改为读真实版本号，读不到时提示无法确认兼容性。
2. 重连后列表漏变化 / 暂存事件可能覆盖较新快照 → D4 先开事件流暂存，再读列表；暂存期有事件则丢弃并补读一次。
3. 推送欠账跨连接代次：断线期间已答的请求误响、重连后重复振铃 → D5 欠账按代重建，已振铃按 eventId 跨代保留（需改 BridleCore 记账）。
4. 搜索默认关闭 → §4 写明 M3 核对 0.2 的启用方式并列入验收。
5. 发布失败回退缺失 → D7 增加回退三条（install.sh 默认回退、dsh 升级失败恢复备份、验收用隔离 DSH_HOME）。
6. CI 漂移无处置 → D8 规定 @latest 失败阻断发版、@alpha 失败只开 issue、确认兼容后才前移固定版本。
7. 桌面端认证未验证 → 目标改为有条件：M0 三项实测通过才纳入，否则移出。
8. 排队与未决交互的重连恢复 → D4 写明从 follow 投影（inbox、userQuestions）恢复，未决请求由 $events 重发（eventId 不变）。
9. §4 漏列 / 错列：图片应内嵌在 session/prompt、历史图片走 session/attachment；权限切换走 /permission 命令；补 Agent 预设、插件清单。
10. 贴 URL 路径端口变化 → cookie 按主机+端口保存，端口变或 401 时要求重贴，列入 M0 验收。
11. follow 快照超帧上限 → maxMessages 保守默认，超限减半重开，列入 M2 验收。
12. 流归属与背压 → D3 规定流记在隧道名下、隧道关闭即取消；每流按字节限队列，超限取消并返回可恢复错误。
13. 旧 app 收不到"需要更新"错误 → D6 明确外层握手不变，Bridle 0.2 保留旧请求帧解析并回旧格式错误；M1 用旧协议测试手机验收；说明不做双栈的理由。
