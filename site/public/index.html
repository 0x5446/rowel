01

It finds you.

The moment your agent blocks on a permission, your lock screen lights up. Not an email. Not a dashboard you forgot to check. The push carries no question — just a fixed sentence and your Mac's name. Open it, and the phone fetches the question over its own encrypted tunnel.

02

The exact command.
Not a summary.

Every approval arrives with the tool call it is for — the full command or the diff — and the reason dsh gives. You decide on what will actually execute, then the Mac carries on while you are still on the train.

03

The relay can't read your code.
Don't take our word for it.

Phone and Mac run a Noise IK handshake with each other, not with us. Our relay forwards sealed frames it holds no key for — and an end-to-end test taps the phone's traffic through a relay and fails if a method name, a session id or a conversation title ever shows up. On the same Wi-Fi the phone usually goes straight to the Mac, and the relay never carries the session.

Every line of it is open source — the app, Bridle, the relay and the protocol — so none of this has to be taken on faith. Read it, or run your own relay.

Set up in a minute.

One prerequisite: a Mac running the DeepSeek Harness.

  1. 1

    Install Bridle on the Mac

    $ curl -fsSL https://rowel.novabox.ai/install | sh

    Needs Node 22+ and git — it stops and says so if either is missing — and dsh 0.2 or newer. Still on dsh 0.1? Add ROWEL_REF=v0.1.7 and use app 1.0; upgrading dsh is one-way, so see the upgrade notes first.

  2. 2

    Pair

    $ bridle pair

    Prints a QR code. With no Bridle running yet, it becomes one and stays running.

  3. 3

    Scan it with Rowel

    Tap Connect a Mac, then I've run it — scan the code. No camera? bridle pair --code gives you a code to type, and you accept the phone on the Mac.

Paired for good — it reconnects on its own. To keep Bridle running after you close the terminal: Ctrl-C, then bridle service install.

Build it yourself

Xcode, brew install xcodegen, iOS 17 or later.

How 
git clone https://github.com/0x5446/rowel.git && cd rowel
ROWEL_TEAM_ID=<your team id> xcodegen generate --spec ios/project.yml
open ios/Rowel.xcodeproj   # pick your iPhone, Run

On a free Apple ID, first comment out aps-environment in ios/Rowel/Rowel.entitlements and set your own PRODUCT_BUNDLE_IDENTIFIER in ios/project.yml. A free signature stops launching after seven days (rebuild to renew), and self-built copies get no lock-screen notifications.

Help.

bridle status says whether Bridle is running, online at the relay, and can see dsh. bridle doctor checks Node, dsh, the relay and pairing.

The app says it can't reach your Mac

Bridle isn't running, or can't reach the relay. Run bridle status on the Mac. If it isn't running, start it with bridle — or bridle service install so it comes back after every login.

Connected, but "dsh isn't running"

Bridle is fine; the DeepSeek Harness isn't. Start it, and the app notices within a few seconds — nothing to restart on the phone.

"dsh asks to sign in"

dsh 0.2 lets in only clients holding the token it printed, and Bridle cannot read that from a dsh someone else started. Run Bridle inside dsh instead: bridle plugin install, then restart dsh. (A dsh that Bridle starts itself needs nothing.)

Pairing fails, or the code is refused

A QR code lasts 10 minutes and works once; running bridle pair again replaces it. A typed code also lasts 10 minutes and is used up the moment a phone enters it — if you decline it on the Mac, or it lapses, run bridle pair --code again.

Works at home, not away

At home the phone reaches the Mac directly; away it needs the relay. bridle status should show the relay as online.

Can't browse folders from the phone

On a Mac, dsh opens a Finder window for its folder picker, which a phone can't use. Rowel falls back to folders you've used and to typing a path. To browse from the phone, add this to ~/.dsh/profiles/web/cordis.patch.yml:

- id: directory-picker
  disabled: true
- insert:
    - id: directory-picker-browse
      name: '@deepseek-ai/dsh-host-directory-picker-browse'
    - id: ui-directory-picker-browse
      name: '@deepseek-ai/dsh-client-ui-directory-picker-browse'

The second entry keeps the desktop web UI's own picker working. Reload the desktop page once.

Search finds nothing

dsh ships with its session index off. Stop dsh, add this to ~/.dsh/profiles/web/cordis.patch.yml, then start dsh again. (Added while dsh is running, it takes every conversation offline until dsh restarts.)

- id: session-query-sqlite
  config:
    path: ':memory:'
    openAt: first-search
A conversation opens empty

Go back, pull down on the list to refresh, and open it again. If its history is long, tap Load earlier messages at the top.

Two harnesses on one Mac

One Bridle serves one dsh, and stays with the one that answered last. Name the one you mean with bridle --dsh http://127.0.0.1:3081 (it starts dsh there if nothing answers; --no-auto-start refuses instead). To serve a second harness alongside, give it its own identity:

ROWEL_HOME=~/.rowel-3081 bridle --dsh http://127.0.0.1:3081
Removing a phone

Forgetting a Mac in the app only affects that iPhone. On the Mac, bridle devices lists paired phones and bridle revoke <prefix> removes one — it is refused at its next handshake; restart Bridle to drop a live connection.

Moving to a new Mac

On the old Mac, bridle backup ~/rowel.bak (encrypted with a passphrase you choose). Stop Bridle there, then on the new one run bridle restore ~/rowel.bak and restart Bridle. Your phones keep working without re-pairing.

After updating

Re-running the installer upgrades in place. Restart Bridle afterwards (or dsh, if Bridle runs inside it) — bridle status says when it is running code from before the update.

Uninstalling

bridle service uninstall if you installed the service, then rm "$(command -v bridle)" and rm -rf ~/.rowel. There is no account to close.

Questions

Does it work with Claude Code, Codex, Cursor or other agents?

No. Rowel is built for the DeepSeek Harness (dsh) and speaks its API — sessions, approvals, models, skills. The harness itself can run many models, DeepSeek, GLM, Qwen and more, and Rowel lets you pick between them.

Is it free?

Yes. The app, Bridle, the relay and the protocol are all MIT-licensed and free.

Does my code leave my Mac?

Only to your own phone, end-to-end encrypted. The relay in between cannot read it, and Rowel never sends anything to an AI service — the agent runs on your Mac with the provider you configured there.

Do the phone and Mac need to be on the same network?

No. On the same Wi-Fi they talk directly; anywhere else they meet through the relay, still end to end encrypted.

Can I run my own relay?

Yes — it is in the repository. Start Bridle with bridle --relay wss://your.host and pair your phone with it.

Is it on the App Store?

It is in App Store review. Until then the same build is on TestFlight.
